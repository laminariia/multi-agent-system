# Юридическое соответствие: Спецификация

> Правила юридического соответствия MAS: защита данных (GDPR, 152-ФЗ), email compliance, хранение и ротация данных, согласие пользователей. Обеспечивает законность работы системы при обработке персональных данных и автоматизированной коммуникации.

## Назначение

Определяет юридические требования, которым подчиняется MAS при обработке данных, коммуникации с лидами и хранении информации. Применяется ко всем компонентам, работающим с персональными данными: Pipeline A (данные клиентов с фриланс-платформ), Pipeline B (email-лиды из публичных источников и enrichment), Telegram-интеграция (мониторинг каналов, DM outreach), Dashboard (отображение и управление данными).

Юрисдикция: Россия (основная), международные клиенты (EU/GDPR, US/CAN-SPAM).

## GDPR и защита данных

### Классификация данных

| Тип данных | Источник | Правовое основание |
|-----------|----------|-------------------|
| Контактная информация клиентов | Фриланс-платформы | Contract performance |
| Файлы проектов | Клиенты | Contract performance |
| Email-лиды (Pipeline B) | Публичные источники + enrichment | Legitimate interest (B2B) |
| Telegram-профили | Публичные каналы | Legitimate interest (B2B) |
| Данные enrichment (Hunter, Apollo) | Waterfall-провайдеры | Legitimate interest (B2B) |

### GDPR (EU-клиенты)

- Правовое основание для B2B cold email: **Legitimate Interest** — допускается для деловых коммуникаций без предварительного согласия.
- Каждое исходящее email-сообщение содержит:
  - Название компании/ИП
  - Физический адрес
  - Ссылку на отписку (unsubscribe) — обязательно
- Право на erasure: обработать запрос на удаление данных в течение **30 дней**.
- Право на access: предоставить копию хранимых данных по запросу субъекта в течение **30 дней**.
- Data minimization: собирать только данные, необходимые для конкретной цели (outreach, проект, enrichment).

### 152-ФЗ (Российские данные)

- Персональные данные граждан РФ хранить на серверах, расположенных в России (Russian-hosted PostgreSQL или Yandex.Cloud / VK Cloud).
- Согласие субъекта **требуется** для:
  - Маркетинговых email физическим лицам
  - Хранения персональных данных за пределами выполнения договора
- Согласие **не требуется** для:
  - B2B-коммуникаций (юридические лица)
  - Исполнения договора
  - Обработки публично доступных данных (email компании на сайте)

## Платформенные политики (общие принципы)

Детальные ToS каждой платформы описаны в `platform-adapters-spec.md`. Здесь — общие юридические принципы:

- **HITL обязателен** для всех операций отправки (bid submission, сообщения клиентам). Полностью автоматическая отправка запрещена на всех платформах.
- **Upwork**: автоматическая отправка заявок **запрещена** (ToS Section 5.3). Допускается только мониторинг и уведомление оператора.
- **Автоматический мониторинг** (поиск, парсинг, RSS) допускается с соблюдением rate limits платформ.
- **Генерация предложений** (bid draft) допускается на всех платформах — это внутренняя операция MAS, не взаимодействие с платформой.
- При обнаружении бана или флага: немедленная остановка автоматизации, документирование причин, ожидание минимум 30 дней перед восстановлением.

## Хранение и ротация данных

### Сроки хранения

| Данные | Срок хранения | Действие по истечении |
|--------|--------------|----------------------|
| Активные клиенты | Срок отношений + 3 года | Архивация |
| Завершённые проекты | 5 лет (налоговое требование) | Удаление |
| Email-лиды без ответа | 90 дней | Удаление |
| Email-лиды с ответом | 12 месяцев | Удаление, если нет сделки |
| Контракты, инвойсы, акты | 5 лет (валютный контроль) | Архивация |
| Переписка, подтверждающая работу | 5 лет | Архивация |
| Telegram-профили (Pipeline B) | 12 месяцев без активности | Удаление |

### Реализация ротации

- Автоматический cron-процесс: ежедневная проверка сроков хранения в PostgreSQL.
- Удаление: soft delete (поле `deleted_at`) с окончательной очисткой через 30 дней.
- Логирование: каждая операция удаления записывается в audit log с указанием причины и количества записей.
- Email-лиды: после 3 отправленных писем без ответа — автоматическая пометка на удаление через 90 дней.

## Согласие и уведомления

### B2B-коммуникации (основной кейс)

- Согласие **не требуется** для первичного B2B cold outreach (legitimate interest).
- При первом контакте указать:
  - Источник получения контактных данных
  - Возможность отказа от дальнейших сообщений
  - Контактную информацию отправителя

### B2C-коммуникации (физические лица)

- Предварительное согласие (opt-in) **обязательно** до отправки маркетинговых сообщений.
- Форма согласия: чекбокс с явным текстом, не предзаполненный.
- Хранить запись о согласии: дата, способ получения, текст согласия.

### Обработка отказов

- Unsubscribe-запрос: обработать в течение **10 рабочих дней** (CAN-SPAM) / немедленно (GDPR best practice).
- Добавить email в suppression list — никогда не отправлять повторно.
- Suppression list хранить бессрочно.

## Email compliance (CAN-SPAM, GDPR)

### CAN-SPAM Act (US-получатели)

Каждое коммерческое email-сообщение содержит:

- Точный заголовок (`From`, `Subject`) — не вводящий в заблуждение
- Идентификацию как рекламное сообщение (если применимо)
- Физический почтовый адрес отправителя
- Механизм отписки (unsubscribe link) — работающий минимум 30 дней после отправки
- Обработка отписки: в течение **10 рабочих дней**

### GDPR Email Requirements (EU-получатели)

- Правовое основание: legitimate interest для B2B cold email
- Unsubscribe: немедленная обработка
- Data subject rights: доступ, исправление, удаление — 30 дней на ответ
- Breach notification: уведомить надзорный орган в течение **72 часов** при утечке данных

### Email Warm-up

- Новые email-домены/аккаунты: **6 недель** warm-up перед production outreach.
- Постепенное наращивание объёма: 5 → 10 → 20 → 50 → 100 писем/день.
- Мониторинг bounce rate (<2%), spam complaints (<0.1%).

### Технические требования

- SPF, DKIM, DMARC — настроить до начала outreach.
- Dedicated IP для email-отправки (не shared).
- List-Unsubscribe header в каждом сообщении.
- Suppression list: проверять перед каждой отправкой.

## Интеллектуальная собственность

### LLM-генерированный код

- AI-генерированный код не подлежит копирайту (прецеденты US courts).
- Модификации человеком — подлежат.
- Весь доставленный клиенту код становится собственностью клиента.
- MAS сохраняет право на переиспользование паттернов и техник (не клиентских данных).

### Open Source зависимости

- MIT, Apache 2.0, BSD — допускаются для коммерческого использования.
- GPL, AGPL — требуют раскрытия исходного кода производного продукта. Не использовать в клиентских поставках без HITL-одобрения.
- Proprietary — требуют лицензии.

## Страхование и ответственность

### Ограничение ответственности

Стандартная контрактная клауза: ответственность ограничена суммой оплаты за услуги. Максимальный предел — $10,000 или стоимость контракта (меньшее из двух).

### Рекомендуемое страхование

| Тип | Покрытие | Ориентировочная стоимость |
|-----|---------|--------------------------|
| Professional Liability | Ошибки в доставленной работе | ~15,000 руб/год |
| Cyber Insurance | Утечки данных | ~30,000 руб/год |
