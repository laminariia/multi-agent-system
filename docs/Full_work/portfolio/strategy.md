### Адаптации под платформы

#### Kwork
- **Тон:** короткий, продающий, конкретный
- **Фокус:** на конкретные кворки (каждый кворк — отдельная услуга с чётким результатом)
- **Особенности:** заголовок кворка = что получит клиент. Описание = процесс + сроки + что входит
- **Пример:** "Создам лендинг для вашего бизнеса за 3 дня — адаптивный, быстрый, с формой заявки"

#### FL.ru
- **Тон:** профессиональный, экспертный
- **Фокус:** опыт, категории специализации, подход к работе
- **Особенности:** упоминание конкретных категорий FL.ru (программирование, дизайн сайтов, скрипты и боты). Портфолио разбито по категориям
- **Пример:** "Команда full-stack разработчиков. Специализация: веб-приложения, Telegram-боты, AI-интеграции. 10+ проектов в портфолио."

#### Fiverr
- **Тон:** дружелюбный, доступный, с акцентом на сервис
- **Фокус:** response time, revisions, пакеты услуг
- **Особенности:** "I typically respond within 1 hour", "unlimited revisions until you're satisfied", "100% satisfaction guarantee"
- **Пример:** "Hey! I'm a full-stack developer specializing in modern web apps and AI integrations. Fast delivery, clean code, and I won't stop until you're happy with the result."

#### Freelancer.com
- **Тон:** формальный, экспертный
- **Фокус:** expertise areas, certifications, metrics
- **Особенности:** перечисление skills (React, Node.js, Python, etc.), упоминание methodology (Agile), акцент на deliverables
- **Пример:** "Full-stack development team with expertise in React, Node.js, Python, and AI/ML integrations. We deliver production-ready solutions with comprehensive documentation and post-launch support."

#### YouDo
- **Тон:** простой, человечный, ориентированный на решение проблем
- **Фокус:** что конкретно можем сделать для клиента, доступность
- **Особенности:** без технического жаргона, акцент на результат для клиента
- **Пример:** "Делаем сайты, приложения, ботов. Объясним простым языком, сделаем в срок. Звоните — обсудим."

#### Telegram
- Адаптация не нужна — мониторим каналы, не размещаем профиль. Отклики идут в личные сообщения, формат свободный.

## 6. Подход к визуалам

### Принцип: НЕ деплоить — верстать для скриншотов

Проекты портфолио не нужно доводить до продакшена. Достаточно:

1. **Визуальные проекты (1, 2, 3, 6, 7, 9):**
   - Сверстать ключевые экраны (HTML + CSS + dummy data)
   - Можно использовать шаблоны/UI-киты как базу
   - Заскриншотить в высоком разрешении
   - Оформить в мокапы устройств (ноутбук, телефон, планшет)

2. **Текстовые проекты (4, 5, 8, 10):**
   - Подробное описание: задача клиента, решение, стек, результат
   - Структура: "Проблема → Решение → Технологии → Результат"
   - Можно добавить схему архитектуры (draw.io / Mermaid)

3. **Мокапы устройств:**
   - Использовать бесплатные mockup-генераторы (Smartmockups, Shotsnapp)
   - Формат: скриншот на экране MacBook + iPhone рядом
   - Повышает визуальную презентабельность в разы

4. **Скриншоты Telegram-ботов (проекты 2, 10):**
   - Запустить бота локально
   - Провести диалог с демо-данными
   - Заскриншотить чат в Telegram

## 7. Авто-пополнение портфолио в MAS (будущее)

После запуска системы в работу — каждый завершённый проект должен автоматически пополнять портфолио.

### Схема

```
Проект завершён
  → Packager Agent сохраняет артефакты (код, скриншоты, описание)
  → Portfolio Agent (новый):
      1. Генерирует скриншоты ключевых экранов
      2. Создаёт описание в формате case study
      3. Адаптирует формат под каждую платформу
      4. Оформляет в мокапы
  → [HITL] — человек проверяет и одобряет
  → Загрузка на платформы (API где возможно, ручная — где нет)
```

### Portfolio Agent — спецификация

- **Тип:** новый агент, расширение Pipeline A
- **Вход:** артефакты проекта из Packager (код, описание, метаданные)
- **Выход:** готовые материалы для портфолио (скриншоты, описания, мокапы)
- **LLM:** DeepSeek V3.2 (генерация описаний) + NanoBanana Pro (мокапы)
- **HITL обязателен** перед публикацией на любую платформу
- **Адаптации:** автоматическая генерация версий для каждой платформы (длина, тон, формат)

### Платформенные API для загрузки

| Платформа | API для портфолио | Статус |
|-----------|-------------------|--------|
| Kwork | Нет публичного API | Ручная загрузка |
| FL.ru | Нет публичного API | Ручная загрузка |
| Fiverr | Seller API (ограниченный) | Исследовать |
| Freelancer.com | Portfolio API (есть) | Автоматизация возможна |

## 9. Стратегия холодного старта

### Принципы

1. **Качество > количество.** Лучше 5 отличных отзывов, чем 20 средних. Каждый проект — потенциальный кейс для портфолио.

2. **Первые проекты ниже рынка.** Скидка 20-30% от рыночной цены на первые 5 проектов. Цель — не заработок, а отзывы и рейтинг.

3. **Фокус на быстрые проекты.** Лендинги, боты, мелкие доработки — то, что можно сдать за 1-3 дня. Быстрый оборот = быстрый набор отзывов.

4. **Мультиплатформенность.** Не класть все яйца в одну корзину. Параллельно развивать присутствие на всех 5 платформах.

### Фазы

#### Фаза 1: Подготовка (неделя 1-2)
- [ ] Заполнить портфолио на всех платформах (10 проектов)
- [ ] Написать и адаптировать "О себе" под каждую платформу
- [ ] Создать кворки на Kwork (5-7 штук)
- [ ] Создать gigs на Fiverr (5-7 штук)
- [ ] Настроить Telegram-мониторинг (список каналов)

#### Фаза 2: Первые заказы (неделя 3-6)
- [ ] Активно откликаться на все релевантные заказы
- [ ] Цены на 20-30% ниже рынка
- [ ] Приоритет: быстрые проекты (лендинги, боты)
- [ ] Просить отзыв после каждого завершённого проекта
- [ ] Цель: 5+ отзывов на каждой платформе

#### Фаза 3: Рост (неделя 7-12)
- [ ] Поднять цены до рыночных
- [ ] Расширить спектр услуг (более сложные проекты)
- [ ] Пополнять портфолио реальными кейсами
- [ ] Оптимизировать кворки/gigs по конверсии
- [ ] Цель: 10+ отзывов, средний рейтинг 4.8+

#### Фаза 4: Масштабирование (месяц 4+)
- [ ] Премиум-цены на сложные проекты
- [ ] Upselling существующих клиентов (Pipeline C)
- [ ] Автоматизация портфолио через Portfolio Agent
- [ ] Выход на международный рынок (Fiverr, Freelancer) с полным портфолио
